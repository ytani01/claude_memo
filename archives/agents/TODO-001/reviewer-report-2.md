## 検討

### 2. PC でフルスクリーンに入ると、スクロールバーが消えて背後と箱自体が横にずれる

**場所**: `claude_memo.html:131-133` `body.fs-lock { overflow: hidden }`。

**何が問題か**: スクロールバーを表示した Chromium（`ignoreDefaultArgs:
['--hide-scrollbars']`）の 1280x500 で実測。

| | `documentElement.clientWidth` | `header` の幅 | フルスクリーンの箱 |
|---|---|---|---|
| 現行・入る前 | 1274 | 1274 | — |
| **現行・入った後** | **1280** | **1280** | x=**195.56** |
| HEAD・入った後 | 1274 | 1274 | x=192.56 |

`overflow: hidden` でスクロールバーが消え、`100vw` 基準の箱の中心が半分だけ右へ動く。
この環境のスクロールバーは 6px だが、実機のデスクトップは 15px 前後なので、
背後のページが 15px 広がり、箱自体も 7.5px ずれる。

**どうなると困るか**: 1280x800 ではレターボックスの上下に 40px の帯が残り、そこに
背後のヘッダー・フッターが見えているので、入る/出るたびに横にガタッと動くのが見える。
実装者の「PC は HEAD と矩形一致」はヘッドレス既定（`--hide-scrollbars` あり）で
測った結果で、その条件ではスクロールバーが無いためこの差が出ない。
挙動の変化として承知のうえなら問題無いが、「PC は変わらない」とは言えない。

### 3. フルスクリーン中の字幕の `bottom` が、アドレスバーの伸縮する端末でずれる（未確認）

**場所**: `claude_memo.html:157-165`（字幕）と `claude_memo.html:200-214`
（`#viewport-frame.is-fullscreen`）。

**何が問題か**: 枠の縦位置は `top/bottom: 0` + `margin: auto` で**包含ブロック
（レイアウトビューポート）の中央**に決まるのに対し、字幕の `bottom` は
`(100vh - レターボックス高) / 2 + 0.75rem` と **`100vh` 基準**で計算している。
iOS Safari や Android Chrome のようにアドレスバーの伸縮で `100vh`（大きい方の
ビューポート）とレイアウトビューポート高が食い違う環境では、この 2 つが一致しない。
差の半分だけ字幕がレターボックスの下端からずれる（390 幅・差 84px なら 42px）。

**どうなると困るか**: 字幕がレターボックスの外（暗幕の上）に浮く、または
スライドに食い込む。**未確認**（デスクトップ Chromium のモバイルエミュレーションでは
アドレスバーの伸縮が再現されないため、ここでは測れなかった）。
`100vh` を使わずに枠を基準にできれば消える種類のずれ。

### 4. スマホ縦のフルスクリーンで、字幕がレターボックスの 34% を覆う

HEAD ではフルスクリーン時のビューポートが画面全体（390x844）だったので、
同じ 75px のバナーが覆う割合は 9% だった。

**どうなると困るか**: せっかくフルスクリーンにしてもスライドの下 1/3 が字幕で隠れる。
上下の暗幕（312px ずつ）は空いているので、通常時のスマホ表示と同じく

面積比が PC とはまったく違う。どちらを取るかは判断が要る。

### 5. スマホではフルスクリーンから出る手段が無い（HEAD からの退行ではない）

## 問題無しと判断したもの（重点項目への回答）

- **1. `setFullscreen()` への集約**: 1280x800 で全経路を実測。ボタン ON/OFF、
  `f` キー、Esc、二重 Esc、`is-fullscreen` だけ手で付けた状態からのボタン、の
  いずれでも `pseudo-fullscreen` / `is-fullscreen` / `fs-lock` の 3 つと
  アイコンが常に揃う。真偽の元は `#player-viewport` の `pseudo-fullscreen` 1 つだけで、
  トグル箇所も 1 か所に集約されている。漏れは見つからなかった
- **3. `#subtitle-banner` の移動による副作用**: JS からの参照は
  `claude_memo.html:1133`（`caption-text`）、`1153`（`subtitle-banner`）と、
  `1549` / `1555` の `hidden` の付け外し、`textContent` の代入だけで、
  親や位置に依存する箇所は無い。`#slide-canvas` の `overflow: hidden` は
  `#player-viewport` の中なので、外に出た字幕は切られない。`margin: 1px` の
  妥当性は指摘 8 のとおり（値は実測で HEAD と一致）
- **5. `767.98px` の境界**: 640 / 767 / 768 / 769 / 1024 で実測。767 は縮小経路
  （`--vp-scale` 0.766、字幕は枠の下）、768 は PC 経路（`--vp-scale` 1.0、
  字幕は枠に重なる）で、二重適用も隙間も無い。`768` ちょうどは Tailwind の
  `md:`（`min-width: 768px`）が効くので、`767.98` と重ならない。
  どちらにも当たらないのは (767.98, 768) の小数幅だけで、Tailwind 自身の
  `max-*` ブレークポイントと同じ慣行。実害は小さい
- **6. 暗幕と `z-index: -1` の重なり順**: 390x844 のフルスクリーンで四隅と中央の
  `elementFromPoint` がすべて `viewport-frame`（暗幕）を返し、ホイールでも
  `scrollY` は 0 のまま。字幕は `z-index: 10000` で枠（9999）より前、
  暗幕（枠の中の -1）は枠の中身より後ろ。意図どおり。
  コンソールエラー・`pageerror` は全サイズで 0 件
- **7. `CLAUDE.md` の追記**: 追記した 2 項目の内容は実装と合っている。
  足りないのは指摘 1（行番号）、指摘 7（比率が 3 か所）、指摘 8（1px の根拠）。
  なお `setupViewportScale()` は PC でも `--vp-scale` を書き込むが、
  使うのがメディアクエリの中だけなのはコメントどおりで問題無い
