# TODO-021. ナレーション後の待ち秒数を選べるようにする

|      | main | 担当 |
|------|------|------|
| 見込み | Opus 5 / effort high | verifier + reviewer |
| 実施 | Opus 5 / effort high | verifier + reviewer（各 2 巡） |

| 担当 | モデル | effort | output | cache_creation | 料金の割合 |
|------|--------|--------|--------|----------------|-----------|
| main | Opus 5 | high | 11,924 | 57,737 | 52% |
| reviewer | Sonnet 5 | high | 29,269 | 99,697 | 32% |
| verifier | Sonnet 5 | medium | 15,259 | 56,073 | 16% |
| 合計 |  |  | 56,452 | 213,507 | 概算 $2.9 |

- verifier は定義のモデルが sonnet。そのまま使った（明示指定しただけで実質は定義どおり）
- reviewer も定義のまま Sonnet 5 / effort high

## きっかけ

読み終わってからスライドを切り替えるまでの待ちが、
`onSlideAudioFinished()` に 2000 ms で直書きされていた。話す速さや場に
合わせて変えたい。

TODO-020 で「待ちも各スライドの尺に含める」ため、待ち秒数を 1 箇所から
参照できる形にしておく必要があり、TODO-020 より先に行った。

## 決めたこと

- 操作は再生操作の並びに置くプルダウン（`select`）。1 秒 / 2 秒 / 3 秒、既定は 2 秒
- 選んだ値は覚えない（再読み込みで 2 秒に戻る）。既存の再生速度と揃える
- **待ちの最中にプルダウンを変えたら、その回の待ちにも即時反映する**
  （レビューの指摘を受けて 2026-09-18 に決めた）。再生速度の変更が
  その場で読み上げをやり直すのと揃えた

## やったこと

`claude_memo.html` のみ。

- 右側の操作の並び（字幕ボタンと再生速度ボタンの間）に `#pause-select` を
  置いた。`speed-btn` と同じクラス指定
- `pauseSeconds`（既定 2）を足し、直書きの 2000 ms を消した
- `schedulePauseTransition()` を新設。`pauseStartedAt`（待ちを始めた時刻）
  からの経過を引いて残りを計算し、`setTimeout` を張り直す。プルダウンの
  `change` で待ち中なら呼び直すので、伸ばしても縮めてもその回から効く
- `slideTransitionTimeout` は消音時の待ち・読み上げの安全タイマーと共用な
  ので、`stopSpeech()` で `pauseStartedAt` を `null` に戻す
- グローバルの `keydown` の除外リストに `'SELECT'` を足した。これが無いと
  プルダウンにフォーカスした状態の Space が再生/一時停止に食われる

## 確かめたこと

verifier と reviewer が 2 巡ずつ。2 巡目は Playwright（Chromium）で
`file://` を開いての実測。

- プルダウンは既定 2 秒、`localStorage` などへの保存は無い
- 直書きの 2000 ms が消え、参照は `pauseSeconds` の 1 箇所に集約されている
- 待ち中に 1 秒へ変えるとすぐ次スライドへ進む。伸ばしたときも正しい
- プルダウンにフォーカスして Space を押しても再生状態が変わらない
- `<script>` を切り出しての `node --check` が通る

## 分担の振り返り

分担は `archives/agents/TODO-021/README.md`。

- **reviewer だけが見つけたものがある。** `select` を足したことで、既存の
  `keydown` の除外リスト（`INPUT`/`TEXTAREA` のみ）の穴が実際に踏まれる
  ようになった件は、仕様のチェックリストには無く、verifier は 1 巡目で
  「指示どおり」と報告している。「動くか」と「良いか」を分けた効果が
  そのまま出た
- **verifier は 1 巡目に実測できなかった**（Playwright が入っていないと
  判断して静的確認だけで返した）。reviewer は同じ環境で Chromium を動かして
  実測している。2 巡目で「実測できる」と伝えたら verifier も実測した。
  **依頼文に「実測の手段はある」と書いておくべきだった**
- **見込みとの差**: 担当の顔ぶれは見込みどおり。ただし 2 巡になり、
  料金は reviewer が 32% と重かった（Playwright での実測を含むため）。
  main が 52% を占めたのは、待ち中の即時反映という仕様変更が途中で入り、
  実装をやり直したため
- **次に同じ規模なら**: 1 巡目の依頼文に「Playwright で実測できる」と
  「レビューで仕様の穴が見つかったら、直す前に利用者へ確認する」を
  最初から入れて、2 巡目を減らす。担当の構成は変えなくてよい
