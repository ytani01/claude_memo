## きっかけ

TODO-041 以降、`README.md` と `docs/` を何度も書き足してきた。項目ごとに
書いた人（担当）が違うため、同じことを指す語が揃っていない箇所や、
直訳調の言い回しが残っていた。文書だけをまとめて見直す機会が無かった。

## やったこと

`CLAUDE.md` / `README.md` / `TODO.md` / `docs/User.md` / `docs/Developer.md`
の 5 ファイルを推敲した。**直したのは日本語だけ**で、手順・コマンド・数値・
ファイル名・リンク先は変えていない。`archives/` は現行仕様ではないので触っていない。

主な直し:

- 「要らない」「無く」→「不要」のように、同じことを指す語を揃えた
- 「〜ので」→「〜ため」、「測れる」→「測定できる」のように、文末と動詞を揃えた
- 冗長な修飾を削った（「スマホでも操作しやすい」→「スマホ対応」など）
- 見出しを 2 つ言い換えた（`docs/Developer.md` の
  「触ると鳴らなくなるもの」→「副作用のある実装」、
  「置き場所は選ばない」→「場所を選ばない」）。どちらもアンカーで
  参照されていないことを確かめてある

verifier の指摘で、main が 2 箇所を戻した。

- `docs/User.md` の「読みを直す」節で、**「長いほうを先に書く」という一般則が
  削られ、`Claude Code` の例だけになっていた**。推敲では「簡潔化」として
  扱われていたが、例からルールを読み取らせる形になり、指示が弱くなる。
  一般則を先に置き、例を後ろに回す形で戻した
- `README.md` の読み上げの項が「Google Translate TTS **または**ブラウザの
  Web Speech API を**ボタンで切り替える**」になっていた。2 つを**切り替えて
  使える**ことが読み取れないうえ、「ブラウザのWeb」でスペースが抜けていた。
  「と」「切り替えられる」に戻した

## 分担の振り返り

- **wording は 5 ファイルを一通り推敲したが、自分が情報を落としたことに
  気づいていない。** 報告では上の 2 箇所とも「簡潔化」として並べており、
  問題として挙げていなかった。verifier が差分の通読で両方を捕まえた。
  **推敲の担当に自己申告させても、削りすぎは出てこない**
- 見込み（wording + verifier）と食い違いは無かった。文書だけの項目でも
  確認を分けた判断は、上の 2 箇所が実際に出たことで裏づけられた
- **次に同じ規模の推敲をやるなら、同じ編成でよい。** ただし依頼文に
  **「簡潔化のために文を削らない。1 文に 2 つのことが書いてあるときは、
  両方残して分ける」**を明記する。Haiku は「簡潔化」を情報の削除として
  実行する傾向があり、今回の 2 箇所はどちらもそれだった。
  main の割合が 65% と高いのは、相談（公開に必要なファイル数、`_rules.js` を
  分けた判断の是非）が同じセッションで走ったため
