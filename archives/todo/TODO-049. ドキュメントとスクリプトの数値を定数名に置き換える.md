# TODO-049. ドキュメントとスクリプトの数値を定数名に置き換える

|      | main | 担当 |
|------|------|------|
| 見込み | Sonnet 5 / effort medium | verifier |
| 実施 | Opus 5 / effort high | verifier |

消費トークンの表は
[TODO-048](TODO-048.%20スライドデータから%20id%20を外す.md) 側にある。
2 件まとめて着手したので、集計の範囲を分けられなかった。

## きっかけ

利用者から「`docs/Developer.md` に `1.4 倍速` と書いてあるが、コードでは
定数に割り当ててあるはず。ドキュメントにマジックナンバーを書かないように」
という指摘があった。見ると `1.4` 以外にも、TODO-024 で名前を付けた値が
数値のまま文書に書かれていた。コードを直したときに文書だけ古くなる。

`tools/measure-duration.py` にも同じ数値が書かれていた（結果表示と
docstring）。スクリプトは 31・32 行に `player.html` の定数の写しを持って
いるので、そこから埋め込めば表示も追従する。

## 決めたこと

- **文書では定数名だけを書き、数値は併記しない。** 併記すると片方だけ
  古くなるので、直す意味が薄れる
- **スクリプトの結果表示は `定数名=値` の形で、実際の値も一緒に出す。**
  実行結果なので値が出るのは自然で、定数から埋め込むぶんずれない

## やったこと

`docs/Developer.md`（6 箇所）

| 今まで | 直したあと |
|--------|-----------|
| 見出し「時間軸に 1.4 を掛けない」 | 「時間軸に `BASE_SPEED_MULTIPLIER` を掛けない」 |
| `1.4 倍が掛かるのは`、`baseSpeedMultiplier` | `BASE_SPEED_MULTIPLIER`（小文字は実在しない名前だった） |
| `1.4 倍速で再生した実測秒数` | `BASE_SPEED_MULTIPLIER` 倍で再生した実測秒数 |
| `180 文字で切る` | `TTS_MAX_CHARS` で切る |
| `textToSpeak.length / 4.5 / ...` | `... / SPEECH_CHARS_PER_SECOND / ...` |
| `3 秒足した時点` | `TTS_END_MARGIN_MS` 足した時点 |
| `40 文字程度に分けて` | `maxLen` の既定値ぶんに分けて |

`docs/Usage.md`（3 箇所）

- `1.4 倍速で再生した実測秒数` → `BASE_SPEED_MULTIPLIER` 倍で再生した実測秒数
- `1 文が長いと 180 文字で切れる` → `TTS_MAX_CHARS` で切れる
- 実行例と `★180 字で切れる` を、直したあとのスクリプトの実際の出力に
  差し替えた

`tools/measure-duration.py`

- docstring 2 箇所の `1.4 倍速` を定数名に
- `--all` の help の「17 枚すべて」を「すべてのスライド」に（枚数はデータ次第）
- 結果表示を定数から埋め込む形にした

```
下書き: 原文 10 字 / 読み 10 字 / 実測 2.376s / BASE_SPEED_MULTIPLIER=1.4 倍速 1.70s -> duration: 2
下書き: 原文 200 字 / 読み 200 字 ★TTS_MAX_CHARS=180 字で切れる / 実測 23.016s / BASE_SPEED_MULTIPLIER=1.4 倍速 16.44s -> duration: 16
```

## 置き換えなかったもの

**定数に対応しない数値はそのまま残した。** `767.98px`（CSS に直接書く値）、
`324 秒`・`0.34〜0.77`・`3px`（実測値）、`15 秒`（Chrome の挙動）。

**`960x540` も残した。** 項目を立てた時点では `SLIDE_BASE_WIDTH_PX` に
置き換える計画だったが、着手して調べると、`960px`・`540px` は
`player.html` の CSS に直接書かれている値（215・216・229・230 行）で、
JS の `SLIDE_BASE_WIDTH_PX` はそれを縮小率の計算に使うための写しだった。
文書が指しているのは枠の寸法のほうなので、`767.98px` と同じ扱いにした。
**この判断を `TODO.md` に反映しないまま確認を依頼したため、verifier が
計画と指示の食い違いとして報告してきた**（下記）。

## 確かめたこと

verifier に確認させた（報告は
[archives/agents/TODO-049/](../agents/TODO-049/verifier-report.md)）。

- 書いた定数名が `player.html` に実在し、値と意味が説明と合っていること
- 置き換えで文の意味が変わっていないこと
- `docs/Usage.md` の実行例が、実際に動かした出力と文字どおり一致すること
  （実測秒数まで一致）
- 180 字を超えたときの `★TTS_MAX_CHARS=180 字で切れる` が実際にその形で出ること
- 残すと決めた数値が誤って置き換えられていないこと、置き換え漏れがないこと

## 振り返り

**分担**: 実装は main、確認は verifier（Sonnet 5 / medium）に分けた。
文書とスクリプトだけの項目だが、確かめる中身が「書式が揃っているか」では
なく「書いた定数名がコードに実在し、値が合っているか」だったので、
main だけで済ませなかった。verifier は実際にスクリプトを 2 パターン
動かして実行例との一致を確認しており、分けた意味があった。

**見込みとの差**: 担当の見立ては合っていた。食い違ったのは
`960x540` の扱いで、**着手して初めて「CSS の直書きで、定数はその写し」だと
分かった**。判断そのものは変えなくてよかったが、`TODO.md` を直さないまま
確認を依頼したせいで、verifier に計画との食い違いを調べさせる手間をかけた。
**方針を変えたら、確認を依頼する前に `TODO.md` を直す。**

**次に同じ規模なら**: 実装は main、確認は verifier の 1 人でよい。
main のモデルは Sonnet 5 / medium で足りる。
