- 集計は `--since '2026-09-18 19:18:44'`（TODO-031 の決着コミットの時刻）で切った

## きっかけ

TODO-030 で `tools/measure-duration.py` をリポジトリに入れたとき、
verifier に `--all` で既存の値を点検させた。**スライド 15（Codex との
共存）だけ実測とずれていた。** 実測 23.064 秒（÷1.4 = 16.47）に対し、
実装は `duration: 17`。3 回測り直しても 16.46〜16.47 秒で安定しており、
測定のぶれではなかった。

## やったこと

**1. 原因を切り分けた。** git を辿ると、このスライドのナレーションは
**初期コミット（`b1b4e6a`）から一度も変わっていない**。
`duration: 17` を入れたのは TODO-018（`0bc8844`）で、そのとき 17 枚すべてを
測って振り直している。つまり**置換表の取りこぼしではなく、TTS サーバ側の
出力が変わったずれ**。TODO-023 が「TTS の秒数はサーバ側の実装に依存する。
同じ手順で測り直しても値が変わることはありうる」と残していた、まさに
そのケースだった。

**2. `duration` を 17 → 16 にした。** 合計は 316 → 315 秒。
`CLAUDE.md` の合計秒数も直した。

## 確かめたこと

verifier が確認した。報告は `archives/agents/TODO-032/verifier-report.md`。

- `tools/measure-duration.py --all` の 17 枚が、`slideData` の `duration` と
  **全枚一致**。スライド 15 のずれが消えた
- `duration` の合計 315 秒、`formatTime(315)` = `5:15` で `CLAUDE.md` と一致
- `#total-time-display` は `5:49`。これは `duration` の合計 315 秒に
  `pauseSeconds`（既定 2 秒）× 17 枚 = 34 秒を足した 349 秒で、
  **`duration` の合計とは別物**。ずれではない
- コンソールのエラー 0 件。17 枚の送りと再生が動く

## 残ること

- **同じずれはまた起きる。** TTS サーバ側が変われば、触っていない
  スライドの実測も動く。**`duration` の合計は「そのとき測った値」**で
  あって、恒久的に正しい値ではない。影響は小さく（送りは読み上げの
  終了イベントで起きるので、音声とスライドはずれない。進行バーが
  待つか先に振り切れるかの違いだけ）、定期的に測り直す決まりは作らない。
  **ナレーションを触る項目のついでに `--all` を走らせれば足りる**
