## きっかけ

**単純に、もっといい声にしたかった。** 既定の `online` は
Google Translate TTS（`translate_tts`）を `Audio` で鳴らしているが、
読み上げが機械的で、スライドの内容に対して声が軽い。

調べる過程で、`translate_tts` が公開された API ではないことに由来する
制約（180 字の上限、Referer を消さないと 404 になる（TODO-002）、
予告なく止まる）も一緒に見ることにした。

## やらないと決めた理由

**現状維持にした。** 声を良くする道は、実行時に鳴らせる範囲には無く、
**事前生成した MP3 を同梱するしかない**と分かったため。その代償
（ナレーションを直すたびの再生成）が、得られる音質に対して重い。
ついでに見た制約も、今は実害になっていなかった。

### 180 字の上限は効いていない

17 枚のナレーションの長さを数えたところ、最長は 152 字（スライド 17）で、
180 字を超えるものは 1 枚も無かった。`speakOnlineTTS()` の
`text.substring(0, 180)` で切り詰められているナレーションは現状ゼロ。
将来ナレーションを長くしたときの天井であって、今の症状ではない。

### 候補ごとの調査結果

| 候補 | 鍵 | CORS | 日本語 152 字の実測 | 判定 |
|---|---|---|---|---|
| Google translate_tts（現状） | 不要 | Referer を消せば 200 | 180 字で切れる | 非公開 API のまま |
| VOICEVOX WEB版 API（tts.quest） | 不要 | `Access-Control-Allow-Origin: *` | 合成完了まで約 40 秒 | ライブ再生に使えない |
| クラウド TTS の無料枠 | 要 | — | — | 静的ページに鍵を置けない |
| edge-tts で事前生成した MP3 | 不要 | 自サイト配信なので無関係 | 即時・150KB・切り詰め無し | 実行時の外部依存ゼロ |
| Web Speech API を既定化 | 不要 | 無関係 | 40 字分割で読み切る | 音声が端末任せ |

**VOICEVOX WEB版 API（`api.tts.quest`）は鍵不要で CORS も通った**が、
名前のとおり「低速」で、合成が順番待ちになる。11 字のテキストは数秒で
用意できたのに対し、152 字のテキストは合成完了まで約 40 秒かかった。
スライド送りには間に合わない。事前生成の道具としてなら使えるが、
キャラクター名のクレジット表記が必須になる。

**事前生成した MP3 の同梱は技術的には成立する。** edge-tts を入れて
152 字のナレーションを合成したところ、即座に 150KB の mp3 ができた。
17 枚で約 2.5MB。これなら 180 字の上限・Referer・サービス停止の 3 つが
同時に消え、`<meta name="referrer" content="no-referrer">` も外せる。
**それでも見送ったのは、ナレーションを直すたびに音声を作り直す手間が
恒久的に残るため。** 実害の出ていない制約と引き換えにするには重い。

## 確かめたこと

- 17 枚の `narration` の文字数を数えた（最長 152 字、合計 2,271 字）
- `curl` で `api.tts.quest/v3/voicevox/synthesis` を叩き、鍵なしで
  `success: true` と `Access-Control-Allow-Origin: *` が返ることを確認した。
  `status.json` を 5 秒おきに見て、152 字が `isAudioReady: true` になるまで
  約 40 秒かかることを実測した
- edge-tts（`ja-JP-NanamiNeural`）で 152 字のナレーションを合成し、
  150KB の mp3 ができることを確認した

## 残ること

ナレーションを 180 字を超える長さに書き換えるときは、切り詰められることを
思い出すこと。そのときに改めて事前生成を検討すればよい。
