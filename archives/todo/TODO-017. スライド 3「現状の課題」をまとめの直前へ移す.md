## きっかけ

スライドの順番を見直したところ、「現状の課題」が 3 枚目にあった。
まだ何も説明していない段階で「トークン消費を減らしたい」「Obsidian 連携を
模索中」と言うことになり、聞き手に前提が無い。

トークンの話は `/clear` と複数アカウント運用のスライドで、ツール連携の話は
plugin と MCP のスライドで出てくる。それを聞いたあとに「残っている課題」として
置くほうが通る。最後の「まとめ」が「自己流で手探りなので意見がほしい」で
締まるので、その直前に置く形にした。

見直しの中で、次の 2 つは変えないと判断した。

- 「主なコマンド一覧」はナレーションが「このあとの説明で登場する」という
  予告なので、導入の直後のまま
- 「TODO.md の実際の記述例」は「タスクごとに担当エージェント」に触れるので、
  「マルチエージェントで役割分担」の後のまま

## やったこと

`claude_memo.html` の `slideData` で、「現状の課題」の要素を 3 番目から
「OpenAI Codex との共存について」と「まとめ」の間へ移し、`// Slide N` の
コメントと `id:` を配列順に 1〜17 へ振り直した。本文・ナレーション・
`duration` は触っていない。

枠の上の `SLIDE nn / 17` と再生リストの番号は `slide.id` を表示している
（配列の添字ではない）ため、`id` の振り直しが必要だった。`slideData` の
参照はそれ以外すべて添字で、`id` で引いている箇所は無い。

## 確かめたこと

verifier が `node` で `slideData` を実際に評価した（報告は
`archives/agents/TODO-017/verifier-report.md`）。

- 要素数 17、`id` は 1〜17 で重複・欠番なし。並びは意図したとおり
- `git diff` 全文の突き合わせで、差分が「ブロックの移動」と
  「`// Slide N` と `id` の数値」だけに収まっていることを確認。
  移動したブロックの中身は `id: 3` → `id: 16` 以外に 1 文字の差も無い
- `playlist-count` の `17 Slides` は要素数と一致

## 残ること

`total-time-display` の直書き `3:15` が、`duration` の合計 214 秒を
再生速度 1.4 倍で割った 152.9 秒（2:33）と合っていない。移動前の HEAD でも
同じ値なので、この項目より前からある不一致。TODO-018 として別に立てた。

## 分担の振り返り

- verifier は、指示した 5 点をすべて実測で返した。`node` で `slideData` を
  eval して要素数・`id` の並び・`duration` の合計を出しており、
  「確認した」で済ませていない。`3:15` の不一致は、HEAD でも同じ値になることを
  確かめたうえで「この項目の範囲外」と切り分けてきた。並べ替えただけでは
  気付けたか怪しい既存の不一致で、確認を分けた効果が出た
- 見込み（main Opus 5 / verifier）と食い違わなかった。分岐も条件式も
  変わらない並べ替えなので reviewer は置かず、それで困らなかった
- 次に同じ規模（1 ファイルの中でブロックを動かし、連番を振り直すだけ）を
  やるなら、同じく main + verifier で足りる。ただし依頼文に
  「node で実際に評価して数字を出す」と書いたことが実測を引き出しているので、
  確かめ方まで指定する書き方は次も続ける。料金の 82% は main 側の
  cache_read で、担当を減らしても下がらない
